# 阎云翔《礼物的流动》与 AI Town 复现分析

**文献**：阎云翔，《礼物的流动：一个中国村庄中的互惠原则与社会网络》（基于黑龙江下岬村田野，英文版 *The Flow of Gifts* 等）。

**项目定位**：AI Town 上的「礼物流动 + 人情网络」可计算仿真（7~14 天课程汇报版）。

---

## 一、复现该书现象是否合适？

### 结论：**合适，但必须“选择性复现 + 机制抽象”，不能追求民族志级还原。**

| 维度           | 判断                                                   |
| ------------ | ---------------------------------------------------- |
| 与老师方向        | ✅ 高度一致：礼物可记录、可检索、影响关系网络                              |
| 与 AI Town 架构 | ✅ 适合用 `giftLedger` + `relationships` + `eventLog` 落地 |
| 与 7~14 天工期   | ⚠️ 只能复现 **5~8 个核心机制**，不能复现整本书                        |
| 学术诚实         | ⚠️ 应声明：是 **受阎云翔启发的简化计算模型**，不是下岬村数字孪生                 |

### 为什么值得做？

1. **理论锚定清晰**：礼物不是装饰性互动，而是维系关系、声望与等级的社会行动（Mauss + 中国人情语境）。
2. **可观测、可对照**：随礼、回礼、时延、不对等互惠都能变成指标和 event log。
3. **区分于“纯聊天 Agent”**：有社会学问题、有假设、有实验，符合作业四要求。

### 为什么不建议“全书复现”？

- 下岬村礼物体系嵌入 **亲属、政治等级、婚礼嫁妆、社会主义时期干部权力** 等厚语境；AI Town 当前无完整经济、宗族、政治结构。
- 民族志中的 **情感、面子、道德评判** 若全靠 LLM 即兴发挥，则不可复现、不可答辩。
- 婚姻交换（第 8 章）与集体化时期等级（第 7、9 章）需要 **更多 NPC、更长模拟时间、更复杂制度**，超出 2 周 MVP。

**推荐表述（汇报用）**：

> 我们受阎云翔对下岬村礼物交换的分析启发，在 AI Town 中实现一个 **简化礼物—人情—关系网络模型**，重点检验：互惠规则与记忆如何影响关系结构与回礼行为。这是对经典人类学命题的 **计算探索**，而非村庄复原。

## 二、书中出现了哪些值得复现的现象？

按 **可行性（7~14 天）** 分为三档。

### A 档：强烈建议复现（MVP 核心）

| #   | 现象（书中）         | 简要说明                      | 仿真中可观察什么                                                       |
| --- | -------------- | ------------------------- | -------------------------------------------------------------- |
| 1   | **礼物分类**       | 仪式性（红白喜事随礼）vs 工具性（办事、拉关系） | 不同 `giftType` 触发不同规则与债务                                        |
| 2   | **礼单 / 馈赠记录**  | 谁何时送了多少，可记账、可回溯           | `giftLedger` + `eventLog` 导出                                   |
| 3   | **义务性随礼与关系培养** | 出席仪式并随礼 = 承认并维系关系         | 缺席/不送 → 关系降、声誉降                                                |
| 4   | **互惠的时间性**     | 非即时对等，而是跨事件、跨时间的“欠情—还情”   | `giftDebt`、回礼延迟 `repayDelay`                                   |
| 5   | **横向 vs 纵向关系** | 同辈对等互惠；向上级往往单向或不对等        | `relationType`: `horizontal` / `vertical_up` / `vertical_down` |
| 6   | **收礼的荣誉与声望**   | “收礼”常与面子、地位相连；随礼有时为争面子    | `face`、`prestige` 随收礼/送礼变化                                     |
| 7   | **人情的道德性**     | 该还不还、该送不送会被视为失礼           | 违约事件 `gift_defaulted` + 公共记忆                                   |

### B 档：可选扩展（时间充裕再做）

| #   | 现象           | 说明                        |
| --- | ------------ | ------------------------- |
| 8   | **礼物交换的不均衡** | 长期不对等仍维持关系（非 Mauss 式立即平衡） |
| 9   | **单向向上馈赠**   | 村民→干部、下级→上级；强化等级          |
| 10  | **关系网络的型构**  | 礼物流塑造 clique、桥接弱关系        |
| 11  | **工具性送礼**    | 为具体目的送礼，事后关系可淡化           |

### C 档：不建议在 MVP 硬做

| #   | 现象                | 原因                 |
| --- | ----------------- | ------------------ |
| 12  | **婚姻交换与彩礼嫁妆转型**   | 需家庭单元、财产、代际        |
| 13  | **社会主义时期六类等级群体**  | 需政治身份、历史阶段         |
| 14  | **完整下岬村亲属与实践性亲属** | 需大规模人口与宗族图         |
| 15  | **深度情感与意义诠释**     | 民族志“深描”，不适合作为硬编码规则 |

## 三、复现这些现象需要什么样的建模？

### 3.1 实体与状态（数据模型）

在 `sociology-extension-schema-rules-hooks.md` 基础上，为阎云翔议题 **最小扩展**：

```
socialActors (已有)
  + face, prestige, renqingBalance (optional)

relationships (已有)
  + relationType: kin | friend | colleague | superior | subordinate
  + giftDebt, lastGiftAt, reciprocityScore

giftLedger (已有)
  + occasion: wedding | funeral | birthday | ritual | instrumental
  + symbolicValue, materialValue
  + status: open | repaid | defaulted
  + dueAt, repaidAt

giftEvents (仪式/场合，简化“红白喜事”)
  + hostId, occasionType, scheduledAt
  + expectedAttendees[], minGiftNorm

eventLog (验收必备)
  + 全链路：intent → ruleCheck → stateDelta → reason
```

### 3.2 规则层（非 LLM）

| 规则 ID   | 对应书中概念 | 规则要点                                                        |
| ------- | ------ | ----------------------------------------------------------- |
| R1 场合礼  | 仪式性礼物  | 特定 `occasion` 触发义务随礼；金额低于 `minGiftNorm` → 失礼                |
| R2 回礼窗  | 互惠的时间性 | `dueAt = t0 + Δ`；窗内回礼加分，超时 `defaulted`                      |
| R3 横向互惠 | 同辈关系   | 价值差 \|Δv\| < ε；长期债务累积触发关系冷却                                 |
| R4 纵向礼  | 单向馈赠   | `vertical_up`：回礼可少于赠礼或仅象征回礼；`vertical_down`：赠礼不足可损 prestige |
| R5 收礼荣誉 | 声望     | 办仪式收礼 → host.prestige↑；随礼竞争（同场多人送）→ 高额者 face↑               |
| R6 人情债  | 欠情     | `giftDebt(B→A)` 累积；对话/合作概率受 debt 调制                         |
| R7 礼单可见 | 礼单     | 任意时刻 query `ledger(A,B)`；公共仪式写入 `publicMemories`            |

**原则**：LLM 输出 `GIVE_GIFT` / `ATTEND_EVENT` / `REPAY_GIFT`；**只有 mutation 通过 R1–R7 才改世界状态**。

### 3.3 Agent 闭环（与老师要求对齐）

```
observe:  附近 NPC、未还礼物、即将举行的 occasion、关系类型与 debt
retrieve: 私有记忆 + 礼单摘要 + 公共仪式记忆
plan:     LLM 或启发式 → {action, target, giftType, amount}
commit:   ruleEngine.validate → giftLedger / relationships 更新
reflect:  写 eventLog + 可选 memory 条目（“上次欠了谁人情”）
```

### 3.4 对照实验设计（受 Port of Mars + 阎云翔启发）

| 实验组 | 操纵                  | 假设（可写进汇报）           |
| --- | ------------------- | ------------------- |
| E1  | 无记忆 vs 有记忆          | 有记忆组回礼更及时、违约更少      |
| E2  | 无互惠规则 vs 有 R2–R4    | 有规则组关系网络更稳定、互惠率更高   |
| E3  | 仅横向 vs 含纵向关系        | 纵向组出现更多非对称礼单（单向流）   |
| E4  | 无仪式场合 vs 有 occasion | 有场合组 prestige 分化更明显 |

**指标**：`reciprocity_rate`, `avg_repay_delay`, `gift_default_rate`, `prestige_gini`, `network_density`, `asymmetric_gift_ratio`（纵向流占比）。

### 3.5 与 AI Town 代码的挂载点

| 书中现象       | Hook                                              |
| ---------- | ------------------------------------------------- |
| 仪式随礼       | 新 input `attendOccasion` / cron 触发 `giftOccasion` |
| 日常/tool 送礼 | `agentOperations` → `giveGift`                    |
| 回礼         | `agentDoSomething` 检测 `giftLedger.status=open`    |
| 关系更新       | `Conversation.stop` + 礼物 mutation 后               |
| 声望/面子      | 仪式结束后 batch update `socialActors`                 |
| 回放         | 导出 `eventLog` JSON/CSV                            |

## 四、复现这些现象有什么意义？

### 4.1 学术/课程意义

1. **连接经典人类学与 ABM/LLM Agent**：把阎云翔的“非制度化人情”转译成可运行、可检验的机制假说。
2. **检验“礼物的流动”是否能在简化世界中涌现**：即使只有 3–5 个 NPC，也可观察债务链、声望分化、非对称流。
3. **方法论示范**：LLM 负责意图与叙事，规则负责社会后果——回应 AI 社会仿真的可解释性争议。

### 4.2 对 AI Town 项目的意义

1. **明确扩展点**：从“会聊天的 NPC”变为“会送礼、会欠情、会还礼的社会行动者”。
2. **可验收**：老师五要素（tick、闭环、规则边界、trace、清楚扩展）均可对照礼物模块检查。
3. **可讲故事**：汇报线 = 问题（人情如何维系网络）→ 理论（阎云翔）→ 模型（schema+rules）→ 实验（E1–E2）→ 局限。

### 4.3 局限（汇报中应主动说明）

- **生态效度**：AI Town 不是中国农村；NPC 数量极少；礼物类型高度抽象。
- **文化特异性**：下岬村规则不能原样套用；纵向礼、干部等级等只能做示意。
- **LLM 噪声**：应用规则层约束 + 固定种子 + 多次重复取均值。
- **不能替代人类学田野**：仿真验证的是 **计算模型**，不是阎云翔结论的统计复刻。
